# 05 · 词表（共同语言基准）

> **性质**：活的共同词汇基准——谈论 hithit 时，词的含义以本文档为准。
> **维护规则**：
> 1. 新概念**先入表再使用**；改定义必须在变更记录留痕。
> 2. 每个词给三层：**程序定义**（代码里是什么）· **业务对应**（以 QQ bot 场景为例的现实对应物）· **落点**（哪个参数/指标/控件）。
> 3. 冻结文档（02/03/04，见 README 冻结标记）里的旧词汇若与本表冲突，以本表为准；尚未接入程序的候选策略词汇标注（待接入）。

## 0. 一句话定位

hithit 模拟的是**字节流和账单，不模拟智能**：把"一群会话各自积累历史、每轮拼一条 prompt 发给 API"翻译成前缀匹配、TTL 过期和四项计费的离散事件流，输出**成本**。**目标函数是经济性（钱），不是命中率**——命中率只是形成成本的机制之一，丢弃信息同样省钱；命中率只用来解释"成本为什么是这样"，不作 KPI。prompt 怎么拼（策略）是它要**评估的对象**，不是它的内置行为。

## 1. 世界层：被模拟的现实

| 词 | 程序定义 | 业务对应（QQ bot 为例） | 落点 |
|---|---|---|---|
| 会话 session | 一条独立前缀链 + 私有历史，用编号区分 | 一个群（或一个私聊用户）；各群话题互不相同 | `workload.n_sessions` |
| 轮 round / 请求 request | 一次"输入→输出"事件，带时刻与会话号 | 这个群被 @ 一次（防抖合并后）并得到一次回复 | 时序图横轴一格 = 一轮 |
| 到达间隔 gap | 同会话相邻两轮的秒数 | 这个群两次被 @ 隔多久 | `workload.request_rate`（指数间隔的均值）或 `gap_hist_*` |
| 稳定前缀 | prompt 开头跨轮、跨会话字节不变的部分，切成 n 块 | 系统提示 / 角色卡 / 工具说明（L0）；全群共享同一份字节 | `workload.stable_prefix_tokens` / `n_stable_blocks` |
| 历史 history | 某会话此前各轮的输入+输出累积成的块列表 | 进上下文的聊天记录（L3）；默认只增长，淘汰是策略的事 | 策略层维护，无直接参数 |
| 新鲜输入 fresh input | 本轮触发带来的新 token 块 | 触发消息本身（L4） | `workload.input_tokens_mean/cv` |
| 输出 output | 模型回复的 token 数 | bot 的回复；下一轮起计入历史 | `workload.output_tokens_mean/cv` |
| 活跃度异质性 | 各会话到达率乘对数正态随机因子 | 有的群火热、有的群长期潜水 | `workload.rate_heterogeneity_cv` |
| 直方图 | 真实数据拟合出的长度/间隔分布表，设置后覆盖参数化分布 | "按真实分布说话"，拟合页产物 | `*_hist_edges / *_hist_weights` |
| 种子 seed | 随机数种子，决定整条事件流 | "重跑同一个世界" | `seed`；运行页"种子数"= 换多个世界取平均 |

## 2. 机制层：API 厂商那一侧

| 词 | 程序定义 | 业务对应 | 落点 |
|---|---|---|---|
| 块 block | prompt 的最小字节单位（同 key = 同字节同长度） | 一段"定稿"字节：一轮对话渲染成的行、一段摘要 | `cache.Block` |
| 前缀匹配 | 沿 prompt 从头逐块比对已存条目，取最深可复用段 | 厂商规则"完全一致的前缀才命中" | `cache.access` |
| 命中 matched | 可复用 KV 的段，按命中价结算 | 不用重新付全价的部分 | 表格"命中读"列；`prices.cached_read` |
| 写入 written | 本次新写入缓存的段，按写入价（**含**读取成本） | 本轮 miss 的部分——这轮付全价，换来下轮起可命中 | 表格"写入"列；`prices.cache_write` |
| 未写尾 tail | explicit 模式断点之后不进缓存的部分 | 主动放弃缓存、纯全价的段 | 表格"未命中输入"列；`prices.input` |
| TTL | 条目存活秒数；命中即续期 | DeepSeek"不再使用后数小时~数天清除"的那个窗口 | `mechanism.ttl` |
| 匹配粒度 chunk | 命中数向下取整的 token 倍数 | DeepSeek 历史口径 64 | `mechanism.chunk_tokens` |
| 最小可缓存 | 低于该长度的前缀不写缓存 | 各家 256~4096 的门槛 | `mechanism.min_cacheable_tokens` |
| 写入模式 mode | auto=整条自动写；explicit=按断点写 | DeepSeek 全自动 vs Anthropic 手动断点 | `mechanism.mode` / `max_breakpoints` |
| 断裂 | 前缀中部字节变化使其后全部 miss | 杀手清单事件：改角色卡、重排历史、窗口截断 | 策略层代价概念（04 M0） |

## 3. 策略层：我们要评估的东西

| 词 | 程序定义 | 业务对应 | 状态 |
|---|---|---|---|
| 策略 policy | compose（每轮用什么块拼 prompt、断点放哪）+ observe（轮后历史怎么增长） | prompt 组装器的行为 | 接口已定 |
| passthrough | 历史只增不删，全量带上 | "聊天记录全部塞进上下文"的朴素上限 | 参照策略 |
| sliding_window | 历史超 `window_max_tokens` 从头截 | "只留最近 N token 记录"的朴素下界 | 参照策略 |
| 水位线淘汰 | 超高水位一次性整块退到低水位 | L3 窗口 2000→800 退避（04 M2） | 待接入 |
| 摘要链 | 淘汰的消息后台压成摘要块追加 | L1 compaction（04 M3） | 待接入 |
| 冻结块链 | 水位线 + 摘要链 + 懒更新档案的组合 | OneKichan 完整策略 | 待接入 |
| 触发策略 | 何时主动发请求的决策规则（主动回复频率、防抖、作息窗口） | "bot 什么时候自动说话" | **待建模**：当前触发时机是外生负载参数（"@ 频率"滑块），本身不可被评估——已知建模缺口（2026-10-05 记） |

## 4. 指标与界面词汇

| 词 | 定义 | 备注 |
|---|---|---|
| 命中率 hit_ratio | matched / prompt（token 加权） | 时序图可看逐请求值 |
| 成本分解 | 未命中输入 / 命中读 / 写入 / 输出 四项 | 与各家 usage 命中字段一一对应 |
| 每请求成本 | cost_total / n_requests | **结论看它**；经济曲线纵轴 |
| 模拟页 | 业务参数面板（群数量/@频率/系统提示长度/缓存保留分钟数…）+ 改参数自动重算 | 没有"运行/扫描"步骤：参数即输入，折线即输出 |
| 时序图 | 逐轮成本/命中率轨迹（单种子），可回放 | 看冷启动、断裂、恢复；横轴一格 = 一轮 |
| 丢弃-经济曲线 | 历史保留上限（0=全丢）→ 每请求成本 | 回答"丢多少历史最划算"；曲线最低点 = 最优丢弃量，"直通"为全保留参考线 |
| 假设页 | 建模自带假设清单（泊松到达、i.i.d. 长度、触发外生、容量无限等） | 解读任何结论前先读 |
| 画像拟合 | profile（真实数据画像）→ 场景 JSON | 数据管道最后一跳 |

## 5. 换算表：业务量 → 参数（把抽象参数锚回业务量）

| 业务说法 | 参数落点 |
|---|---|
| "30 个群" | `n_sessions: 30`（默认值） |
| "这个群平均 15 分钟被 @ 一次" | `request_rate: 0.00111`（= 1/900，**默认值就是这个**） |
| "每天被 @ 100 次的群" | `request_rate ≈ 0.00116`（= 100/86400） |
| "系统提示 / 角色卡 800 token" | `stable_prefix_tokens: 800` |
| "用户每轮打 ~150 token、bot 回 ~250" | `input_tokens_mean: 150` / `output_tokens_mean: 250`（默认值） |
| "模拟一天" | `sim_time: 86400`（默认值） |
| "DeepSeek 缓存保几小时~几天" | `mechanism.ttl: 10800 ~ 172800`（**默认 300 只是 5 分钟，偏短，跑 DeepSeek 记得改**） |
| "DeepSeek flash 价"（示例价，用前复核官方） | `prices: input 2 / cached_read 0.03 / cache_write 2 / output 4`（¥ / 1M token） |
| "Anthropic 式手动断点 + 1.25× 写溢价" | `mode: explicit` + `cache_write = 1.25 × input` |
